# Проверка и публикация

## Автоматические проверки

1. `npm ci` устанавливает зависимости строго по lock-файлу.
2. `npm run vendor -- --check` сверяет vendored библиотеку и лицензию с установленным пакетом.
3. `npm test` запускает тесты Node: правила, результаты, часы, сохранения, компьютер.
4. `npx playwright install chromium` устанавливает тестовый браузер.
5. `npm run test:e2e` запускает локальный HTTP-сервер и проверки в двух размерах экрана.

`npm run check` объединяет проверку форматирования и шаги 2, 3 и 5. В CI браузер и системные зависимости устанавливаются отдельно. Сервер привязан к `127.0.0.1`, отказывает в выдаче скрытых путей и `node_modules`; не используйте его как публичный production-сервер.

При ошибке Playwright сохраняет screenshot и trace в `test-results/`. Открыть trace: `npx playwright show-trace <путь-к-trace.zip>`. Эти артефакты не коммитятся.

## Ручной приёмочный сценарий

- Открыть страницу на широком экране и на телефоне: доска квадратная, страница не прокручивается горизонтально.
- Начать игру с другом без часов. Проверить выбор, подсветку, перестановку выбора, взятие и историю.
- Сыграть `f3 e5 g4 Qh4#`: должно появиться сообщение о победе чёрных. Ходы заблокированы; отмена снова разрешает игру.
- Проверить рокировку: король переходит на две клетки, ладья передвигается автоматически.
- Проверить превращение: доступны четыре фигуры; закрытие диалога не выполняет ход.
- Начать игру с компьютером за чёрных: доска развёрнута, компьютер ходит первым.
- Сделать ход против компьютера и сразу нажать «Отменить» или начать новую партию: старый ответ не должен менять новую позицию.
- Начать `3+2`: после хода добавляются 2 секунды. После сворачивания/перезагрузки реально прошедшее время учитывается.
- Скачать PGN после мата, сдачи и ничьей: проверить историю и результат в совместимом просмотрщике.
- Перейти к доске клавишей Tab, играть стрелками и Enter; проверить F, U, Escape, фокус в диалогах.
- Заблокировать хранилище браузера: партия работает, сообщение предупреждает об отсутствии автосохранения.
- Проверить реальные Safari/iOS и Firefox перед заявлением поддержки этих браузеров: CI использует Chromium и мобильную эмуляцию.

## GitHub Pages

Проект сохраняет статическую структуру исходного сайта. Для релиза нужен корневой `index.html` вместе со `styles.css`, `favicon.svg`, `src/` и `vendor/`. Все ссылки относительные; абсолютных путей от корня домена в приложении нет.

После прохождения проверок и слияния PR проверьте настройки Pages и дождитесь штатного развёртывания GitHub. Откройте сайт именно в `/chess.io/`, начните партию против компьютера и убедитесь, что Worker загружен. Workflow `checks.yml` не публикует сайт и не меняет настройки Pages.

Для отката используйте обычный revert коммита и повторное штатное развёртывание. При изменении формата сохранений повышайте версию ключа или добавляйте миграцию; не интерпретируйте несовместимый JSON как новую схему.
