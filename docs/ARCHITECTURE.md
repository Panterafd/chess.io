# Архитектура

## Единственный источник позиции

`Game` содержит экземпляр `Chess` из vendored chess.js. DOM не хранит шахматные правила: допустимые поля берутся из `chess.moves({ square, verbose: true })`, а каждый ход ещё раз проверяется в `Game.move()`. Компьютер и подсказки проходят тот же путь проверки, что и человек.

`boardResult()` определяет мат, пат, недостаток материала, троекратное повторение и правило 50 ходов. При любом результате новые ходы блокируются. Сдача, соглашение и просрочка часов хранятся отдельно от позиции. Отмена снимает результат и повторно вычисляет его по возвращённой позиции.

## Часы

`Game` принимает внедряемую функцию `now`, что позволяет проверять часы без реальных задержек. `tick()` вычитает фактически прошедшие миллисекунды из времени активной стороны. Интервал UI лишь инициирует обновление: частота фоновых таймеров не определяет затраченное время.

Перед ходом часы обновляются; при истечении времени ход отклоняется. После хода добавляется increment и переключается активная сторона. История снимков хранит значения непосредственно перед ходом (после списания потраченного времени, до increment). Отмена восстанавливает этот снимок. До первого хода часы не идут.

В сохранении находится временная отметка. При восстановлении время отсутствия списывается со стороны, чей ход не завершён. Используется системное время, поэтому изменение часов ОС может влиять на результат; это локальный инструмент без серверного арбитража.

## История и сохранение

JSON версии 1 содержит настройки, начальный FEN, SAN всех ходов, снимки часов, результат и `savedAt`. При загрузке проверяются форма данных, диапазоны значений и допустимость ходов. История проигрывается заново, поэтому сохраняются права рокировки, возможность взятия на проходе, счётчик 50 ходов и повторения позиций. Один FEN не содержит достаточной информации для определения троекратного повторения.

`localStorage` используется при ходе, изменении результата, уходе со страницы и раз в секунду во время игры. Ошибка записи не прерывает партию. PGN формируется из реальной истории и получает итоговый тег `Result`; текст истории выводится через `textContent`.

## Компьютер

Каждый расчёт выполняется в новом модульном Web Worker. Используется negamax с alpha-beta, итеративным углублением, упорядочиванием взятий и ограниченными продолжениями взятий/защиты от шаха на горизонте. Оценка учитывает материал, продвижение пешек и размещение лёгких фигур ближе к центру.

| Уровень                 | Максимальная глубина     | Бюджет  |
| ----------------------- | ------------------------ | ------- |
| Начальный               | 1 полуход + продолжения  | 200 мс  |
| Средний                 | 3 полухода + продолжения | 700 мс  |
| Продвинутый / подсказка | 4 полухода + продолжения | 1800 мс |

При превышении бюджета берётся лучший ход последней **полностью законченной** итерации. Если ни одна не закончена, возвращается допустимый резервный ход. Бюджет проверяется между узлами; стоимость одной операции генерации ходов может немного увеличить реальное время. Передаётся PGN для сохранения повторений в дереве поиска.

Отмена, новая партия и завершение игры вызывают `worker.terminate()` и меняют идентификатор запроса. Ответ применяется только при совпадении идентификатора и FEN. Это не позволяет старому расчёту сделать ход в новой партии. При ошибке Worker показывается кнопка повторения.

## Интерфейс и доступность

Доска — 64 нативные кнопки с подписями клетки, цвета и фигуры. В последовательности Tab присутствует одна клетка; стрелки перемещают фокус с учётом ориентации доски. Enter/пробел выбирают фигуру или ход. Фокус сохраняется при перерисовке.

Диалоги используют нативный `<dialog>`: фокус удерживается внутри, Escape закрывает диалог. Статус партии объявляется через `aria-live`, часы не создают объявление каждые 100 мс. Все SVG локальные. Анимации отключаются при `prefers-reduced-motion`.

## Границы

- Нет аккаунтов, сети, рейтинга, турниров, сервера времени и защиты от изменения локальных данных.
- Автоматические ничьи — правило этого приложения, а не полная процедура FIDE.
- Проверка возможности мата при просрочке охватывает очевидные случаи; сложные мёртвые позиции не решаются исчерпывающе.
- Нет движка уровня Stockfish, дебютной базы и эндшпильных таблиц.
- Сохраняется одна партия, без синхронизации между вкладками/устройствами и без импорта PGN/FEN.
- Приложение не использует service worker: первая загрузка требует хостинга; после загрузки вычисления и игра локальные.
